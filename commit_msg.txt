fix: sidebar clicks did not navigate — NavigateCommandProperty had no DP callback

## Root cause
In Sidebar.xaml.cs, `NavigateCommandProperty` was registered without a
`PropertyMetadata` callback while `ShellStateProperty` had one. Consequence:

  1. Sidebar ctor runs `Populate()` synchronously.
  2. WPF then resolves the bindings from MainWindow.xaml into the
     `NavigateCommand` and `ShellState` DPs.
  3. `OnShellStateChanged` fires `Rebind()` → `Populate()` again, but at
     this moment `NavigateCommand` was still null in the typical binding
     order.
  4. The new `OnNavigateCommandChanged` callback DID NOT EXIST, so the
     second Populate() never ran after the command finally arrived.
  5. Every SidebarItem child kept its initial null `NavigateCommand`.
  6. Click on a sidebar item ran SidebarItem.OnSelected:
        if (NavigateCommand is { } cmd && cmd.CanExecute(Route))
            cmd.Execute(Route);
     Since `NavigateCommand` was null, this whole block fell through
     silently — no exception, no log, no Frame.Navigate, no
     ShellState.CurrentRoute update. Page never swapped.

## Fix
app/BioCentri.App/src/components/Nav/Sidebar.xaml.cs
    - Added `new PropertyMetadata(null, OnNavigateCommandChanged)` to
      the NavigateCommandProperty registration.
    - Added the matching `OnNavigateCommandChanged` callback which
      mirrors the existing `OnShellStateChanged` pattern: invoke
      `s.Rebind()` → `Populate()` so children pick up the now-non-null
      ICommand.
    - Inline comment documents why this callback is essential so the
      next refactor doesn't accidentally drop it.
