fix: WPF startup crash — GradientStop.Color can't reference SolidColorBrush resources

## Root cause
MainWindow.xaml was assigning SolidColorBrush resources (Brushes.Ink.950,
Brushes.Accent.IndigoGlow, Brushes.Accent.EmeraldGlow) to GradientStop.Color
on three GradientBrush definitions (one Linear, two Radial). WPF does NOT
implicitly convert SolidColorBrush → Color in StaticResource lookups, so
MainWindow.InitializeComponent() threw a XamlParseException. The catch in
MainWindow.xaml.cs surfaced a MessageBox titled "Startup Error" while the
process stayed alive; MainWindow itself never rendered.

## Fix
- app/BioCentri.App/src/styles/Brushes.xaml
    Added paired Color keys mirroring each affected SolidColorBrush.Color:
      Colors.Ink.950            = #060606
      Colors.Ink.900            = #0A0A0B
      Colors.Accent.IndigoGlow  = #40818CF8
      Colors.Accent.EmeraldGlow = #3034D399
    Inline comment explains why the pair is required (GradientStop.Color
    takes Color, not Brush; designers must keep hex in sync).

- app/BioCentri.App/src/windows/MainWindow.xaml
    5 GradientStop.Color edits: 3 stops on the vertical backdrop gradient +
    Indigo aura + Emerald aura now reference Colors.* instead of Brushes.*.
